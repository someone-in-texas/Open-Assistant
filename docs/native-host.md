# Native companion

The optional companion provides two no-relay modes:

- **Private BYOK:** stores an OpenAI project API key in the OS credential manager and calls the fixed Responses API endpoint.
- **Codex subscription (experimental):** delegates ChatGPT login, credential refresh, model discovery, and turns to a compatible `codex app-server` child process over stdio.

The host is a single Rust binary using 4-byte little-endian native-messaging framing, a 1 MiB hard limit, strict tagged requests, normalized bounded stream events, cancellation, and at most four concurrent operations. It has no listening socket or plugin loading. BYOK permits only the configured GPT-5.6 model allowlist and rejects redirects.

## Development build and install

Build with the Rust 1.97.1 toolchain pinned by `rust-toolchain.toml` and:

```bash
pnpm build:native
pnpm smoke:native
```

For a local macOS development install:

```bash
apps/native-host/installers/macos/install.sh \
  "$PWD/apps/native-host/target/release/open-assistant-native-host"
```

On Windows PowerShell:

```powershell
pnpm build:native
.\apps\native-host\installers\windows\install.ps1 `
  -BinaryPath "$PWD\apps\native-host\target\release\open-assistant-native-host.exe"
```

These commands register the absolute binary path for extension ID `open-assistant@example.org`. They do not sign the binary or create a production installer. After registering it, open extension Settings, choose a native mode, grant optional native-messaging access, and save.

## Private BYOK

Choose **Private local companion (BYOK)**, select an allowlisted model, and store an OpenAI project API key. The plaintext field is cleared after storage; the extension persists only the selected model. The companion reports only whether a key exists. Use a dedicated project with appropriate spend limits.

## OpenAI sign-in through Codex

Install Codex CLI 0.145.0 or newer on `PATH`, choose **OpenAI sign-in through Codex (experimental)**, and select **Sign in with OpenAI**. Leave the model override blank to use the account default, or enter a model exposed by app-server model discovery. The companion fails closed when Codex is unavailable, too old, authenticated with an API key instead of ChatGPT, or returns an incompatible schema.

Codex runs with a dedicated Open Assistant profile and an empty, permission-restricted workspace. Apps, browser use, code mode, computer use, image generation, memories, multi-agent, plugins, shell, skill search, and web search are disabled. Threads are ephemeral and read-only, approvals are denied, network access is false at the turn boundary, and any server tool request is rejected. Only text deltas or a strict edit proposal cross back into the extension.

Compatibility is based on OpenAI's official [Codex app-server](https://learn.chatgpt.com/docs/app-server) and [Codex authentication](https://learn.chatgpt.com/docs/auth) documentation plus the schemas generated by the installed CLI.

Dedicated Codex profile locations:

- macOS: `~/Library/Application Support/OpenAssistant/Codex`
- Windows: `%LOCALAPPDATA%\OpenAssistant\Codex`
- Linux development: `$XDG_DATA_HOME/open-assistant/codex` or `~/.local/share/open-assistant/codex`

## Release requirements

macOS installs the manifest under `~/Library/Application Support/Mozilla/NativeMessagingHosts/`, uses the `org.mozilla.open-assistant` Keychain service, and requires a universal Developer ID signed/notarized/stapled release. Windows installs per-user under `%LOCALAPPDATA%`, registers `HKCU\Software\Mozilla\NativeMessagingHosts\org.mozilla.open_assistant`, uses Credential Manager, and requires Authenticode. Installer templates are under `apps/native-host/installers`; release packaging must verify signatures before attachment.
