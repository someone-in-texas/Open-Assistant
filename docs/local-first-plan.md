# Local-first provider plan

Status: planning only. This document does not authorize or implement a new authentication or model path.

## Direction

Make the signed native companion the default trust boundary for non-mock model access. The Firefox extension should send bounded, user-approved requests over native messaging; the companion should own provider credentials, outbound model traffic, cancellation, and response streaming. A hosted relay can remain optional for users who prefer zero local setup, but it should not be required for the OSS distribution.

The existing native host is the starting point: it already restricts callers to the extension, stores an OpenAI API key in the OS credential store, calls a fixed HTTPS endpoint, rejects oversized messages, and keeps secrets out of extension storage.

## Provider paths

### 1. Local BYOK

Ship the current direct OpenAI API path first.

- Complete signed and notarized Windows/macOS packaging before making it a supported release path.
- Keep the API key in Keychain or Credential Manager and expose only `store`, `delete`, and redacted status operations.
- Stream normalized protocol events back to the extension instead of returning raw provider responses.
- Add cancellation, bounded queues, explicit model allowlists, response-size limits, and stable error categories.
- Recommend a dedicated OpenAI project with spend limits. Never place the key in extension storage, environment variables, command arguments, URLs, or logs.

### 2. ChatGPT subscription through Codex

Prototype this as an optional, clearly labeled integration after BYOK ships. Codex app-server supports deep local product integrations and owns a browser or device-code ChatGPT login flow, including Plus/Pro plan state and Codex rate-limit reporting.

- Have the native companion spawn `codex app-server` over stdio; do not open a TCP listener.
- Let app-server own and refresh ChatGPT credentials. Do not extract, copy, or expose its tokens to the extension.
- Identify this path as `Codex subscription (experimental)`, not as generic OpenAI API OAuth.
- Use the stable app-server schema generated by the installed Codex version and negotiate capabilities at startup.
- Run with a dedicated empty working directory, a read-only/deny-by-default permission profile, no automatic approvals, and no shell or filesystem actions. Browser actions must continue through this project's reviewed agent-policy layer.
- Confirm product-fit and entitlement behavior with OpenAI before graduating the adapter. If the Codex surface or plan does not authorize a request, fail closed and offer BYOK or a local model.

This path should not be implemented by replaying ChatGPT web sessions, scraping cookies, or treating a consumer session token as an OpenAI API bearer token.

### 3. Fully local models

Add a provider adapter for a loopback-only, OpenAI-compatible Responses endpoint or a narrowly supported local runtime.

- Permit only `localhost`, `127.0.0.1`, or `[::1]`; reject redirects and non-loopback resolution.
- Require explicit user selection and display the active provider/model on every conversation.
- Apply the same prompt/context separation, output validation, action policy, and cancellation behavior as remote providers.
- Treat local model output as untrusted. Local inference removes credential and hosting costs, not prompt-injection risk.

## Security invariants

- One versioned request/stream protocol across hosted, BYOK, Codex, and local-model adapters.
- Credentials never cross into extension JavaScript.
- No provider can bypass explicit context review, source boundaries, Markdown sanitization, or action confirmation.
- Native messaging and child-process stdio are preferred over listening sockets.
- All message, context, output, queue, and execution durations are bounded.
- Logs contain provider state and error categories, never prompts, page content, credentials, authorization URLs, or raw provider bodies.
- Private-window data remains memory-only and is never reused across profiles or providers.
- Provider changes invalidate active context and conversations unless the user explicitly starts a new request.

## Delivery sequence

1. Specify a provider-neutral native protocol and add threat-model cases for credential storage, process spawning, cancellation, and local endpoint attacks.
2. Finish signed native-host installers, updater/removal behavior, and cross-platform release verification.
3. Move direct API responses behind normalized streaming events and ship local BYOK as the first supported no-relay mode.
4. Build a small Codex app-server compatibility spike with generated schemas, managed ChatGPT login, rate-limit display, and all execution tools disabled.
5. Add the loopback local-model adapter and a conformance suite shared by every provider.
6. Decide whether the hosted relay remains an opt-in convenience deployment or a separately maintained distribution.

## Graduation criteria

A provider path is ready only when secrets never enter extension storage, cancellation leaves no orphan process/request, all protocol bounds have adversarial tests, provider switching fails closed, signed install/uninstall is verified on supported platforms, and the same agent-policy suite passes against recorded streams from that provider.
